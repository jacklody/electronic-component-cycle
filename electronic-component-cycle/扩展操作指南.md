# 🛠️ 扩展操作指南

## 🎯 最简单的方式：用可视化配置工具

**99%的扩展需求都不需要改代码！**

直接双击打开项目根目录下的 `config-manager.html` 文件，在浏览器里点点鼠标就能完成所有配置：

| 想做什么 | 操作步骤 | 耗时 |
|----------|----------|------|
| 加新品类 | 「品类管理」标签页 → 输入品类名 → 点添加 → 去「生成代码」复制 | 10秒 |
| 加新原因类型 | 「原因类型」标签页 → 选涨跌方向 → 填原因名和关键词 → 点添加 → 复制代码 | 5分钟 |
| 加新预警规则 | 「预警规则」标签页 → 选周期类型 → 填触发信号和预测 → 点添加 → 复制代码 | 1分钟 |
| 加新噪音词 | 「噪音过滤」标签页 → 输入噪音关键词 → 点添加 → 复制代码 | 10秒 |
| 对接新数据源 | 在搜索循环里加新的API调用即可 | 10分钟 |
| 加消息推送 | pipeline结束后加webhook/企业微信/飞书机器人调用 | 10分钟 |

## 📝 手动修改指南（如果需要深度定制）

如果你需要更深度的定制，按下面的步骤改就行。

### 1. 添加新品类

打开 `scripts/auto_cycle_pipeline.py`，找到 `EventDiscovery` 类的 `__init__` 方法：

```python
self.categories = [
    # 在这里加你要的品类，直接加字符串就行
    "你的新品类",
    # 被动元件
    "MLCC", "片式电阻", ...
]
```

✅ 不需要改其他任何地方，智能体自动会搜索这个品类的历史行情。

---

### 2. 添加新的原因类型

#### 第一步：加关键词
在 `RCAAnalyzer` 类里：
- 如果是**上涨原因**，加在 `ROOT_CAUSE_KEYWORDS` 字典里
- 如果是**下跌原因**，加在 `DOWNTURN_CAUSE_KEYWORDS` 字典里

```python
ROOT_CAUSE_KEYWORDS = {
    # 原来的原因...
    "你的新原因名称": ["关键词1", "关键词2", "关键词3"],
}
```

#### 第二步：加类型判断
在 `determine_cycle_type` 方法里加判断：
```python
if "你的新原因名称" in cause_analysis["root_cause"]:
    return "你的新周期类型名称"
```

#### 第三步：加对应的预警规则
在 `generate_warning_template` 方法的 `templates` 字典里加对应的预警：
```python
"你的新周期类型名称": [
    {"signal": "触发信号1", "level": "🔴红色预警", "prediction": "预测结果1"},
    {"signal": "触发信号2", "level": "🟢绿色预警", "prediction": "预测结果2"},
]
```

✅ 完成，智能体自动会识别新的原因类型并触发对应预警。

---

### 3. 添加新的预警规则

在 `RCAAnalyzer.generate_warning_template` 方法里，找到对应周期类型的数组，直接加字典就行：

```python
"供给收缩型上涨": [
    # 原来的预警...
    {"signal": "你的新触发信号", "level": "🟠橙色预警", "prediction": "你的预测结果"},
],
```

✅ 不需要改其他地方，自动生效。

---

### 4. 添加新的市场噪音词

在 `RCAAnalyzer.FALSE_NARRATIVES` 列表里直接加字符串：

```python
FALSE_NARRATIVES = [
    # 原来的噪音...
    "新的噪音词",
]
```

✅ 智能体自动会在分析时识别并排除这些噪音，不会让它们影响判断。

---

### 5. 对接新的数据源

在自动搜索的循环里加新的数据源调用就行，比如：

```python
# 原来的通用搜索
results = general_search(query)

# 加新的数据源，比如行业网站、特定数据库
results += your_custom_data_source.search(query)
results += industry_website.search(query)
```

只要返回的结果格式是 `{"title": "...", "content": "...", "source": "..."}`，就可以直接喂给pipeline，自动处理。

---

### 6. 添加消息推送/报警

在pipeline处理完事件后加推送逻辑就行，比如企业微信机器人、飞书机器人、邮件：

```python
result = pipeline.auto_analyze_new_event(...)

# 如果触发了红色预警，发消息通知
if "🔴红色预警" in result.get("warning_level", ""):
    # 调用webhook发消息
    requests.post("你的webhook地址", json={
        "msgtype": "text",
        "text": {"content": f"⚠️ 电子元器件行情预警：{result['warning_level']}\n{result['action_suggestion']}"}
    })
```

## 🔧 高级扩展

### 添加新的校验规则

在 `scripts/cycle_analyzer.py` 的 `ComponentCycleAnalyzer` 类里加新的校验方法，然后在 `run_mcp_analysis` 里加对应的分支就行。

### 添加新的分析维度

在知识图谱的事件结构里加新字段，pipeline会自动保留，不会影响已有数据。

### 对接数据库

把知识图谱从JSON文件换成SQLite/MySQL，只需要改 `AutoKnowledgeGraphUpdater` 类的读写方法，其他逻辑不用动。

## 💡 常见问题

**Q: 我改了配置，之前的数据会丢吗？**
A: 不会。所有历史数据都存在知识图谱JSON文件里，改配置不影响已有数据。

**Q: 我加错了怎么办？**
A: 用git回滚就行，或者直接在配置工具里删掉错的，重新生成代码。

**Q: 可以对接我们公司内部的价格数据库吗？**
A: 可以，只要把内部数据转成标准格式喂给pipeline就行，自动分析自动入库。

**Q: 可以每天自动跑吗？**
A: 可以，用Windows计划任务或者cron，每天跑一次自动搜索最新行情，触发预警自动发消息给你。
